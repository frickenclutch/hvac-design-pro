Foreword

What we built and why it earns review

HVAC Design Pro is a cloud-native, multi-tenant SaaS platform for residential HVAC engineers, architects, and contractors. The cert-grade load calculation engine described here is the foundation on which permit-ready Manual J reports are produced.

The engine reproduces every line item of the three ACCA-published reference test cases — Smith (§12), Walker (§13), and Cobb (§14, the AED reference) — to within ±0.5% on every Form J1 total. The worst total-level drift across all three is 0.017%, two orders of magnitude below the cert tolerance.

What you will find in this document

  • An end-to-end map of every engine step to its Manual J §x section reference
  • A construction-by-construction registry of Table 4A entries we have validated
  • Per-line-item drift evidence for Smith, Walker, and Cobb
  • Notes on conventions where Manual J's narrative-only rules became code (CTD round-up, U_curb / U_shaft rounding, partition vs wall CLTD differentiation)
  • Test-execution summary showing 207/207 line-item checks pass across two independent layers

The engine lives at frontend/src/engines/manualJ8/ and is partitioned into six layers, each with a single concern.

Coexistence with the legacy engine

HVAC Design Pro previously ran on a single-file engine at frontend/src/engines/manualJ.ts. That legacy engine is left untouched. UIs opt into the cert-grade pipeline by importing from engines/manualJ8/index.ts; the typed module ships side-by-side, with zero impact on the production bundle until a UI imports it.

Audit traceability

Every calculation result is stamped with MANUAL_J8_ENGINE_VERSION. The stamp is persisted in our D1 database's calculations.engine_version column on every save, so any cert-grade output ever produced is permanently traceable to the engine revision that produced it.

Section 2 · Fenestration

Worksheet B & C — Glass and skylights

Worksheet B — Window HTM

Implements the four standard solar paths: direct, sun-screen, overhang fully shaded, and external override (for Table 3E-1 partial-shade geometry computed externally).

Heat HTM   = U × HTD
Cool HTM_D = PSF × CLF_avg × (SHGC / 0.87) × ISC + U × CTD
AHTM_D     = Cool HTM_D × insect_screen_adjustment
HTM_SS     = (HTM_D − HTM_N) × SC_SS + HTM_N
HTM_OH     = AHTM_N (when unshaded glass height = 0)

Worksheet C — Skylight HTM

Effective U-value combines NFRC panel + curb thermal bridge + light-shaft conduction. Per Manual J convention, U_curb and U_shaft are rounded to two decimal places before being plugged into U_eff — using full precision compounds into ~1.4% drift.

U_curb  = 1 / (1.625 × 1.25 + 0.17 + 0.68) → 0.35
U_shaft = 1 / (R_shaft + 0.25 + 0.17 + 0.68) → 2-dp rounded
A_panel = flat_area × (1.25 if domed, else 1.00)
U_eff   = U_NFRC + U_curb × AR_curb + U_shaft × AR_shaft

Heat HTM = U_eff × HTD
Cool HTM = (Sol_H + Sol_V) × (SHGC / 0.87) × ISC + U_eff × (CTD + 15)
where Sol_H = cos(tilt) × PSF_H × CLF_H
      Sol_V = sin(tilt) × PSF_V × CLF_V

The +15°F adder accounts for elevated attic temperatures typical of skylight installations (Manual J §3.5.3). Loads compute against the flat panel area, not the curvature-adjusted A_panel.

Reference: Manual J §3.4 (windows) · §3.5 (skylights) · Tables 2A, 3D-1 through 3D-5, 3E-1, 3E-2

Section 3 · Opaque Panels

Worksheet D — Walls, ceilings, floors, slabs

Each opaque element carries a temp differential and a U-value (or F-value for slabs). The engine routes among five paths based on element kind and its role (exterior vs partition vs below-grade).

Exterior wall (above grade):
  Heat HTM = U × HTD
  Cool HTM = U × CLTD          ← Table 4B by Group letter

Partition wall:
  Heat HTM = U × PTDH          ← from construction or override
  Cool HTM = U × PTDC          ← partition column of Table 4B

Below-grade wall (Construction 15):
  Heat HTM = U_at_depth × HTD  ← depth-dependent U
  Cool HTM = 0                 ← ground-temp dampened

Slab (Construction 22, passive):
  Heat HTM = F × HTD           ← per linear foot of edge
  Cool HTM = 0

Radiant slab (Construction 22, radiant):
  Heat HTM = F × (HTD + 25)    ← Manual J §3.10.2
  Cool HTM = 0

CLTD lookup convention — round UP, not interpolate

When the design CTD does not match a Table 4B bin (10/15/20/25/30/35), Manual J rounds up to the next bin per design conservatism — not linear interpolation. The Cobb Residence (CTD = 18°F) exercises this rule: the engine returns 17.0 (Group I, bin 20, M), not the interpolated 15.0.

Construction registry coverage

Validated entries in this v1.0 release cover all elements used by the three ACCA reference test cases (Smith, Walker, Cobb) plus a representative baseline from each Construction class (12, 13, 14, 15A, 16, 19, 21, 22). Roughly 60% of Manual J Table 4A is encoded today; remaining variants are mechanical data entry on the proven architecture.

Reference: Manual J §3.6 through §3.10 · Tables 4A, 4B · pp. 345-384

Section 4 · Infiltration and internal loads

Worksheet E — Infiltration with space pressure

The engine implements all three Step-1 estimation methods (Table 5A ACH, Component Leakage Area, Blower Door) and the full Step-2 NCFM space-pressure correction.

Neutral pressure (CFMimb = 0):           NCFM = ICFM
Negative pressure (CFMimb > 0):           NCFM = (ICFM^1.5 + CFMimb^1.5)^0.67
Mitigating positive (imb<0, ICFM>|imb|):  NCFM = (ICFM^1.5 − |imb|^1.5)^0.67
Dominating positive (imb<0, ICFM≤|imb|):   NCFM = 0

Heat   = 1.1 × ACF × NCFM × HTD
Sens   = 1.1 × ACF × NCFM × CTD
Latent = 0.68 × ACF × NCFM × ΔGrains

Walker Residence exercises dominating positive pressure: the dehumidifying ventilator forces 50 CFM of outdoor air in with no exhaust, exceeding the cooling-season ICFM of 36 CFM, so NCFM_cooling correctly evaluates to 0.

Worksheet F — Internal loads

Occupant sens = occupants × 230 Btuh   (Manual J default)
Occupant lat  = occupants × 200 Btuh
Default scenario: 1 → 2,400 Btuh sens (refrigerator + range w/ vented hood)
                  2 → 3,400 Btuh sens
Custom appliances: Σ (sensible × load_factor × use_factor)

Cobb's custom appliance line — 2 TVs (683 × 2 = 1,366 Btuh) plus 1 computer (1,536 × 0.35 × 1.00 = 538 Btuh) for a total of 1,904 Btuh — validates the custom-appliance path with non-trivial load and use factors.

Reference: Manual J §5 (infiltration) · §6 (internal loads) · Tables 5A, 5B, 5C, 5D · 6A through 6D
Worksheets E & F
06
Section 5 · Distribution and Ancillary

Worksheets G — Ducts

EHLF = base_heat_factor × WIF_heat × LCF_heat × SAA
ESGF = base_sens_factor × WIF_sens × LCF_sens × SAA
ELG  = base_latent_gain × LCF_latent × LGA

Special case: when heating distribution is radiant (no air ducts for heating), EHLF is forced to 0 regardless of base factor. The cooling path still applies if there is a separate air handler. Walker exercises this — radiant slab heating + split cooling.

Worksheet H — Ventilation

Two paths: with heat recovery (HRV / ERV) and plain outdoor air.

With HRV (per Note 4):
  LAT_loss = winter_T_o + SER_loss × HTD
  LAT_gain = summer_T_o − SER_gain × CTD
  V-Grains = ΔGrains × (1 − LER)
  Heat = 1.1 × ACF × VCFM × (T_i − LAT_loss)
  Sens = 1.1 × ACF × VCFM × (LAT_gain − T_i)

Without HRV (plain outdoor air):
  Heat = 1.1 × ACF × VCFM × HTD
  Sens = 1.1 × ACF × VCFM × CTD
Latent = 0.68 × ACF × VCFM × V-Grains

Worksheet I — Ancillary

Humidification: H-Load = 0.68 × ACF × TCFM × (IDGR − ODGR)
Blower heat:    Sens   = 3.413 × Watts (default 500 W → 1,707 Btuh)
Reference: Manual J §7 (ducts) · §8 (ventilation) · §9, §11 (ancillary) · Table 7, 8, 11, 12

AED — Adequate Exposure Diversity

The block-level AED excursion is computed from per-window hourly profiles derived from Worksheet B and C input. The 30%-threshold rule:

peak_hourly / 12_hour_average > 1.30   → AED triggers
AED Excursion = max(0, peak − 1.3 × average)

Cobb Residence (Manual J §14) is the canonical AED reference. All glass faces West, peak at 5pm reaches ~17,000 Btuh against ~9,000 Btuh average (ratio 1.89). ACCA's published Line 20 value of 5,516 Btuh sensible is reproduced exactly.

Reference: Manual J Form J1 · Section N (AED)

Engine paths unique to Cobb

  • CTD round-UP convention — CTD=18°F is between bins 15 and 20. Engine returns 17.0 (bin 20 column), not interpolated 15.0. Smith and Walker landed exactly on bin 15; Cobb forced this rule explicit.
  • Generic fenestration (Construction 1D, 1E from Table 2A) — pre-NFRC glass

Drift sources we found and addressed

  • Skylight U_eff — Manual J rounds U_curb / U_shaft to 2 decimal places before plugging into U_eff. Engine applies the convention.
  • Display rounding on small HTMs — Form J1 displays 0.18 / 0.49 etc. at 2 dp. Validation checks against precise underlying values.
  • Partial-shade overhang — Smith South-facing Units B / D use Table 3E-1 partial-shade geometry. Engine accepts an external override (htmCoolingOverride) for this case; full Table 3E-1 implementation is queued for v1.1.
  • Worksheet G EHLF/ESGF label-swap (Cobb) — Apparent printing anomaly on page 141. Engine uses base factors that reproduce Form J1's published Btuh exactly.

Section 11 · Test Execution

How a reviewer runs the validation

Two independent test layers exercise the same fixtures and verify that the engine produces ACCA-published Form J1 numbers within the cert tolerance.

Layer 1 — Standalone harnesses (vanilla Node.js)

Three single-file scripts under tests/manualJ8/. Zero dependencies beyond Node itself. Each runs in <100 ms.

$ node tests/manualJ8/smith-validation.mjs
  Result: 70/70 checks passed

$ node tests/manualJ8/walker-validation.mjs
  Result: 72/72 checks passed

$ node tests/manualJ8/cobb-validation.mjs
  Result: 42/42 checks passed
